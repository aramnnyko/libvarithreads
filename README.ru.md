# libvarithreads

> Конфигурируемая библиотека потоков пользовательского уровня. Pre-alpha. В разработке.

_Читать на: [English](README.md) | **Русский**_

Одна кодовая база, много конфигураций — выбирается на этапе компиляции.

---

## Зачем это

Способ тонко настроить, какой режим выполнения и планировщик нужен
задаче — не переключаясь между разными проектами. Одна кодовая база,
выбор на этапе компиляции: собираешь ровно ту конфигурацию, которая
подходит нагрузке, без диспетчеризации во время выполнения и без
неиспользуемого кода.

## Статус

Сейчас на стадии **симулятора**: планировщик **DRRD**
(Deficit Round Robin с динамическими весами) верифицируется
в отдельном симуляторе. Рантайма пока нет.

См. [ALGORITHMS_DRRD.md](ALGORITHMS_DRRD.md) — описание планировщика.

### Планировщик: DRRD

DRRD — это вариант Deficit Round Robin с динамическими весами. Состав
потоков может меняться в середине цикла; доли пересчитываются на лету.
Гарантия даётся на уровне потока, а не только группы. В долгосрочной
перспективе: за полный цикл без блокировок поток получает ровно
`priority` квантов; в циклах с блокировкой недостача переходит в долг
и компенсируется позже.

Ключевые свойства:

- **Пропорциональное распределение** — за полный цикл каждый поток
  получает количество квантов, равное его приоритету. Поток с
  приоритетом 3 получает 3 кванта за цикл. Потоки в группе имеют
  одинаковый приоритет (группа — это класс эквивалентности по
  приоритету), поэтому вес группы = `priority × count`, и внутри
  группы потоки делят его поровну (round-robin).
- **Динамические веса** — потоки можно добавлять и удалять в середине
  цикла, без остановки планировщика, с сохранением гарантии
  пропорционального распределения.
- **Учёт долга** — если поток заблокирован, его планировочное решение
  расходуется, но квант не доставляется. Поток запоминает это как долг.
  При разблокировке он получает отложенный квант: за одно решение —
  два кванта вместо одного. Другие потоки получают своё обычное число
  решений; долг не уменьшает их долю в долгосрочной перспективе.
- **O(G) на каждую операцию** — стоимость зависит от числа групп `G`,
  но `G ≤ 10` по замыслу, поэтому практически константа.

#### Когда подходит

- Смешанные нагрузки, где разным классам потоков нужны разные доли
  процессорного времени.
- Системы с потоками, которые часто блокируются и разблокируются —
  механизм долга сохраняет долговременную справедливость.
- Сценарии с динамическим составом потоков: серверы, пулы задач,
  где потоки создаются и завершаются постоянно.
- Встраиваемые системы с небольшим числом уровней приоритета
  (архитектурно — до 10 групп).

#### Когда не подходит

- **Системы жёсткого реального времени с дедлайнами.** DRRD даёт
  пропорциональную долю, но не даёт верхней границы на задержку или
  джиттер. Для дедлайнов нужен EDF или аналогичный планировщик.
- **Много уровней приоритета.** Алгоритм рассчитан на ≤10 групп;
  при большом числе приоритетов O(G) перестаёт быть константой.
- **Частая смена приоритета потока.** Смена приоритета — это
  удаление из одной группы и добавление в другую. При этом
  сбрасывается накопленный долг потока и пересчитываются дефициты
  всех групп. При частой смене накладные расходы растут.
- **Многоядерные системы.** DRRD — планировщик для одного ядра.
  Балансировка между ядрами — отдельная задача, не его.

Алгоритм подробно описан в [ALGORITHMS_DRRD.md](ALGORITHMS_DRRD.md).
